## Context

Урок хранит `targetDate:string|null` и `status:'upcoming'|'completed'`. Планировщик `makePlan` берёт предстоящие уроки с датой не раньше сегодня, сортирует по дате и считает нужный темп. Настройки хранятся одной записью `settings`. Снимок данных собирается в `loadSnapshot` и попадает в React через `useSnapshot`. Экран урока читает запись напрямую из базы через `useLesson`, а сохранение `saveLesson` записывает объект целиком.

Исходные уроки: 1.1 проведён без даты, 1.2 с датой 2026-09-18, 1.3 и 1.4 без даты.

## Goals / Non-Goals

Goals:
- Один раз заданное расписание даёт даты всем предстоящим урокам без даты.
- Ручная дата урока уважается и сдвигает следующие уроки.
- Прошедший урок не требует ручной отметки.
- Планировщик и экраны, читающие дату урока, не меняются.

Non-Goals:
- Ручной порядок уроков перетаскиванием.
- Исключения в расписании (праздники, отмены) и несколько расписаний.
- Автоматический перенос непроведённого урока вперёд.

## Decisions

### Расписание в настройках

`Settings` получает поле `schedule:{startDate:string|null;weekdays:number[]}`. Дни недели по ISO: 1 — понедельник, 7 — воскресенье. По умолчанию `{startDate:null,weekdays:[]}` — расписание не задано. Расписание считается заданным, когда есть дата и хотя бы один день. При загрузке снимка и при восстановлении копии отсутствующее поле дополняется значением по умолчанию, поэтому старые копии читаются без миграции.

Альтернатива — отдельная таблица расписания — отклонена: настроек одна запись, и расписание не имеет самостоятельной истории.

### Смысл даты урока

Заполненное поле даты означает «задана вручную» и служит якорем. Пустое поле означает «по расписанию». Схема не меняется, но правка урока идёт только через `updateLesson(id,patch)`: операция читает сырую запись из базы и применяет частичное изменение. Так вычисленная дата из снимка не может попасть в базу. `saveLesson` удаляется; `createLesson(title)` и импорт создают урок без даты.

### Вычисление дат — чистая функция

Новый модуль `src/domain/schedule.ts`:

- `lessonOrder(a,b)`: сравнивает уроки по числам из названия. Из названия берётся первая последовательность вида `1.2` или `12`; компоненты сравниваются как числа поэлементно, более короткий префикс раньше. Уроки без номера идут после уроков с номером, между собой по `createdAt`, затем по `id`.
- `nextLessonDay(day,weekdays,inclusive)`: ближайший день расписания начиная с `day` (включительно или строго после). День недели считается по календарной строке `YYYY-MM-DD` в UTC, как остальные функции над днями в `learning.ts`.
- `scheduleLessons(lessons,schedule):Lesson[]`: возвращает копии уроков с заполненным `targetDate` и полем `dateSource:'manual'|'schedule'` для уроков с датой. Алгоритм: уроки сортируются `lessonOrder`; курсор — первый день расписания не раньше `startDate`; далее по порядку:
  - урок с датой в базе сохраняет её как `manual`; курсор становится `max(курсор, следующий день расписания строго после этой даты)`;
  - урок со статусом `completed` и без даты пропускается, курсор не двигается;
  - остальные получают день из-под курсора как `schedule`; курсор переходит на следующий день расписания.
  Если расписание не задано, уроки без даты остаются без даты, уроки с датой получают `manual`. Возвращаемый порядок совпадает с исходным порядком массива, чтобы не менять поведение экранов.

`Lesson` получает необязательное поле `dateSource`. Оно заполняется только в снимке; в базу не пишется, потому что записи идут через `updateLesson` с частичным изменением, а `commitImport` и `createLesson` строят записи сами.

### Подключение на границе хранилища

`loadSnapshot` дополняет настройки значением по умолчанию и возвращает `lessons` уже пропущенными через `scheduleLessons`. Планировщик, экраны «Сегодня» и «Уроки», список уроков слова получают готовые даты без изменений. Экран урока переходит с `useLesson` на поиск урока в снимке. `useLesson` остаётся для мест, которым нужна сырая запись, либо удаляется, если таких мест не осталось.

Альтернатива — переписывать даты всех предстоящих уроков в базе при каждом изменении — отклонена: пять точек мутации, скрытые массовые записи и риск расхождения.

### Закрепление прошедших уроков

Операция `settleLessons(now,database)`: читает сырые уроки и настройки, вычисляет даты, и для каждого урока с вычисленной датой раньше сегодняшнего дня в зоне пользователя, у которого статус не `completed` или дата в базе пуста, записывает эту дату и статус `completed`. Операция идемпотентна: повторный запуск ничего не пишет. Вызывается после `ensureSeed` при запуске и при каждой смене календарного дня, пока приложение открыто (через существующий хук часов в `App`).

После закрепления урок становится якорем, поэтому смена расписания не трогает прошедшие занятия и не может вернуть их в предстоящие.

Ручная кнопка «Отметить проведённым» делает то же для одного урока: записывает его текущую вычисленную дату и статус `completed`. «Вернуть в предстоящие» меняет только статус; дата остаётся ручной. Урок без даты и без расписания отмечается проведённым без даты, как сейчас.

### Экраны

«Уроки». Над списком карточка «Расписание». Свёрнутый вид: «Пн и Чт, первое занятие 18 сентября» либо «Не задано — даты уроков назначаются вручную». Кнопка раскрывает форму: поле даты «Первое занятие» с `min` = сегодня, семь переключателей дней недели с `aria-pressed`, кнопки «Сохранить», «Отмена» и, для заданного расписания, «Убрать расписание». Ошибки: «Выберите хотя бы один день недели.», «Дата первого занятия — не раньше сегодня.». В списке у предстоящего урока с ручной датой в описании добавляется «дата вручную».

«Урок». Поле даты и «Сохранить дату» остаются. Под полем подсказка: для даты по расписанию — «Дата по расписанию. Своя дата сдвинет следующие уроки.»; для ручной даты предстоящего урока — кнопка «Вернуть в расписание», которая очищает дату. Сообщение после сохранения не меняется.

Создание урока и импорт: поле «Дата занятия» удаляется. Подпись формы создания подсказывает, что дата назначится по расписанию, если оно задано.

### Исходные данные

Урок 1.2 сохраняет дату 2026-09-18 как ручную: после задания расписания 1.3 и 1.4 получают дни расписания после неё. После 18 сентября операция закрепления переводит 1.2 в проведённые.

## Risks / Trade-offs

- Дата урока в базе и в интерфейсе различаются для уроков по расписанию. Смягчение: одна точка вычисления в `loadSnapshot`, запись только через `updateLesson`, тест, что сохранение правки не пишет вычисленную дату.
- Дата первого занятия в прошлом закрепила бы несколько уроков разом. Смягчение: форма не принимает дату раньше сегодня; операция закрепления работает только с датами, которые действительно прошли.
- Порядок по номеру в названии зависит от именования. Смягчение: уроки без номера не теряются, а идут после, по дате создания; название можно переименовать.

## Migration Plan

Миграции нет. При первом запуске новой версии настройки дополняются полем расписания по умолчанию; поведение без расписания совпадает с текущим. Откат безопасен: старая версия игнорирует неизвестное поле настроек и читает даты уроков как раньше.
