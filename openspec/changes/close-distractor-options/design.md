## Context

Мотивация — в proposal.md, требования — в `specs/adaptive-learning/spec.md`.

- `optionsFor(word, pool, type, random)` берёт ключ ответа (перевод для узнавания и понимания на слух, написание для аудирования) и передаёт его в `optionsAmong`. Та отбрасывает своё слово и совпадающие после нормализации ответы, перемешивает остальное и берёт три. Меньше трёх различных — `[]`, и задание с выбором недоступно.
- Пул — `optionPool(48)`: весь словарь, если в нём не больше 48 слов, иначе несколько случайных порций. О составе занятия и уроках пул ничего не знает, и соседи по уроку могут в нём оказаться.
- Варианты строятся в четырёх местах:
  - `startSession` → `exerciseFor` → `objectiveExercise`;
  - `recordAnswer` → `easierRetry(item, database)` → `easierExercise`, до транзакции записи (`src/storage/ops.ts:84`);
  - `prepareObjectiveSession` для старых сессий, внутри транзакции по `sessions`, `words` и `phrases`;
  - `buildWordExercise` и `wordExerciseOptions` на экране слова. Экран и `useWordExercises` читают данные функциями `storage/queries.ts` напрямую, а не через `SessionSource`.
- Связь слова с уроками — таблица `lessonItems` с индексами по `unitKey` и `[lessonId+position]`. Слово может входить в несколько уроков.
- Позиции в уроке идут с пропусками: `removeFromLesson` и снятие авторских связей при обновлении пакета удаляют записи, не сдвигая позиции, а фразы занимают позиции наравне со словами. Окно считается по позициям, а не по словам, поэтому в нём может оказаться меньше двенадцати соседей.
- `selective-data-access` требует загружать полное содержимое только для выбранной сессии и ограниченного пула вариантов. Уроки курса бывают большими, поэтому «все слова всех уроков слова» — неограниченная выборка.
- `splitWriting(greek).article` отделяет определённый артикль. Множество `ARTICLES` включает и οι/τα, и винительные τον/την/τους/τις.
- `shuffle` — Фишер–Йетс, тратит `len − 1` вызовов `random`. Уже сейчас число вызовов зависит от размера пула.
- Эталонный тест плана `tests/plan-golden.test.ts` фиксирует сессию при заданном `random`. В фикстуре есть уроки, поэтому близкие слова в ней будут.

## Goals / Non-Goals

**Goals:**
- Одна чистая функция отвечает на вопрос «какие три неверных варианта у этого слова». Все четыре места вызывают её с разными наборами близких слов.
- Задание с выбором доступно ровно тогда, когда и сейчас: когда во всех источниках вместе есть три различных неверных ответа.

**Non-Goals:**
- Варианты фраз: у фраз свой пул, и он остаётся случайным.
- Смысловая близость (синонимы, общая тема по метаданным): таких данных у слов нет. Урок — единственная доступная тема.
- Близость по написанию или звучанию (минимальные пары): отдельная задача, для неё нужна своя метрика.

## Decisions

**1. Шесть групп с фиксированным порядком, а не взвешенная случайность.**
Функция `distractorsFor(word, sources, type, random)` получает `sources: { close: Word[]; pool: Word[] }`. Сначала она готовит кандидатов:
- из обоих источников убираются само слово и кандидаты, чей нормализованный ответ совпадает с ответом слова (как сейчас в `optionsAmong`);
- из `pool` убираются слова из `close` по id. Иначе случайная выборка может принести третьего соседа по уроку в обход потолка;
- каждый кандидат получает номер группы: источник × форма в порядке требования;
- повторы по нормализованному ответу не схлопываются заранее: ответ входит во все свои группы, а при заполнении мест его берёт первая группа, до которой дошла очередь, остальные его пропускают. Схлопывание по номеру группы до заполнения не подходит: номер близкого слова той же формы зависит от того, исчерпан ли потолок, и ответ, который есть и в словаре той же формы, мог бы достаться группе «сверх потолка» и дать третий близкий вариант при живом кандидате словаря. Прежнее поведение `Map` в `optionsAmong` (остаётся последний) не подходит тем более: слово словаря той же формы уходило бы в группу близких другой формы.

Затем места заполняются группами в порядке из требования: близкие той же формы до потолка → словарь той же формы → близкие той же формы сверх потолка → то же для другой формы. Внутри группы порядок случайный. Итоговые четыре варианта перемешиваются ещё раз.

Порядок выбран так, потому что форма — главная подсказка в аудировании: вариант другой формы отбрасывается сразу, и выбирать приходится из трёх. Замкнутый набор занятия подсказывает слабее, поэтому потолок уступает форме. Источник уступает обоим.
Отвергнуто:
- Веса вида «близкое слово в 3 раза вероятнее». Такой подбор сложнее проверять тестом, а гарантии «не больше двух из занятия» он не даёт.
- Сортировка по форме внутри источника (первая редакция). Два глагола урока тогда вытесняют существительные словаря, и подсказка формой остаётся.
- Разные правила для аудирования и узнавания. Для узнавания форма тоже полезна: русские переводы существительных и глаголов различимы. Одно правило проще проверять.

**2. Потолок в два близких варианта.**
В занятии из 6–10 слов при трёх близких вариантах каждый перевод занятия появится в нескольких карточках. К середине занятия ответ начнёт находиться исключением «это уже было правильным у другой карточки». С двумя близкими вариантами хотя бы один вариант незнаком по занятию, поэтому сравнивать приходится со словом, а не с историей занятия. Потолок — константа в домене, её можно подобрать по данным позже без изменения требований.

**3. Форма слова — наличие артикля.**
`sameForm(a, b) = !!splitWriting(a.greek).article === !!splitWriting(b.greek).article`. Для аудирования это убирает подсказку прямо в написании. Для узнавания и понимания на слух это грубо отделяет существительные от глаголов и прочих слов, и русские переводы тоже оказываются однородными.
Отвергнуто: совпадение самого артикля (ο/η/το). Выбор сужается втрое. В аудировании при этом пропадает полезная проверка рода: вариант с другим артиклем — честный неверный ответ.

**4. Соседи по уроку — окно по позиции, функция `storage/queries.ts` и метод источника.**
`lessonMates(wordIds, database): Promise<Map<string, Word[]>>`:
1. `lessonItems` по `unitKey` слов дают пары «урок, позиция».
2. Для каждой пары диапазонный запрос по `[lessonId+position]` от `position − 6` до `position + 6` даёт соседние ссылки. Читаются только ссылки на слова, фразы пропускаются.
3. По id соседей загружаются слова (`bulkGet`), удалённые и само слово отбрасываются.

Окно ограничивает полное содержимое: не больше 12 соседей на урок слова, то есть не больше `12 × число уроков слова × размер занятия` слов на сборку занятия. Этим выполняется требование `selective-data-access` об ограниченном пуле вариантов. Окно `LESSON_MATES_RADIUS = 6` — константа, её можно подобрать позже.
Отвергнуто:
- Все слова уроков. Большой урок курса даёт сотни полных слов на каждую сборку, ошибку и экран слова.
- Случайная выборка `OPTION_POOL` соседей. Она тоже ограничена, но недетерминирована, и равенство Dexie-реализации со снимком пришлось бы проверять статистически. Окно детерминировано, а соседи по месту в уроке обычно ближе и по теме.

Функция экспортируется, потому что экраны слова читают `storage/queries.ts` напрямую. `SessionSource.lessonMatesOf` — обёртка над ней в Dexie-реализации. `snapshot-source.ts` реализует тот же метод по снимку.

Где что считается близким:
- **`startSession`:** один вызов на всё занятие. `close` = соседи по урокам ∪ слова карточек занятия (они только что прочитаны и живые).
- **`easierRetry`:** сигнатура становится `easierRetry(item, session, database)`, сессию передаёт `recordAnswer`. `close` = соседи по урокам ∪ живые слова сессии. Слова сессии — снимки из `session.items`, поэтому они перечитываются из `words` по id, удалённые отбрасываются. Весь подсчёт остаётся до транзакции записи, как сейчас: область транзакции `recordAnswer` не расширяется.
- **`prepareObjectiveSession`:** близкие слова читаются до транзакции. Соседи по урокам и живые слова берутся по id из сессии, прочитанной вне транзакции. Внутри транзакции остаются только чтение сессии и запись элементов. Если за это время сессия успела измениться, варианты могут опереться на чуть устаревший набор близких слов. Это не портит данные: варианты — не прогресс.
- **`WordExerciseScreen` и `useWordExercises`:** занятия нет, `close` = соседи по урокам. В `useWordExercises` `lessonMates` вызывается внутри того же `useLiveQuery`, что и `optionPool`, иначе доступность будет считаться по неполным данным. В зависимости запроса добавляется `word?.id`: сейчас там `[]`, потому что пул от слова не зависит, а соседи зависят. Без этого при переходе между словами доступность считалась бы по соседям прошлого слова. Запрос только читает, изоляция экрана от записи не нарушается.

Отвергнуто:
- Брать только слова занятия. В занятии из повторений слова одного урока встречаются редко, и выигрыша почти не будет.
- Хранить близкие слова в сессии. Они нужны только в момент подбора.
- Расширить транзакцию `prepareObjectiveSession` на `lessonItems`. Этот путь тоже рабочий, но чтение до транзакции повторяет подход `recordAnswer` и держит транзакцию узкой.

**5. Доступность считается по объединению источников.**
`wordExerciseOptions` и `objectiveExercise` передают в `distractorsFor` те же `sources`. Условие «три различных неверных ответа» проверяется на `close ∪ pool`. Слово, которому сейчас доступно узнавание, не потеряет его.

## Risks / Trade-offs

- **[Сдвиг потока `random` меняет эталонный тест плана]** Число вызовов `random` не фиксировано ни сейчас, ни после изменения: Фишер–Йетс тратит `len − 1` вызовов на группу, и сумма по группам зависит от данных. Варианты и порядок плиток в `tests/plan-golden.test.ts` изменятся наверняка. → Типы упражнений измениться не должны: `chooseTypeFor` не использует `random`, а доступность вариантов не сужается (решение 5). Ожидания вариантов и плиток обновляются с объяснением в коммите. Изменение типов или состава сессии считается ошибкой.
- **[Близкие слова раскрывают ответ другой карточки]** → потолок в два варианта (решение 2). Показ перевода соседа среди вариантов — не подсказка к его собственному заданию: там перевод нужно выбрать по греческому слову.
- **[Форма важнее потолка: иногда три близких варианта]** → только когда в остальном словаре нет трёх слов той же формы. Это маленький словарь, в котором замкнутый набор неизбежен и сейчас.
- **[Лишние запросы при сборке занятия]** → на каждое слово занятия приходится один индексный запрос `lessonItems` по `unitKey` и по одному диапазонному запросу на урок слова. Полных слов читается не больше 12 на урок слова (решение 4).
- **[Окно отрезает тематически близкие слова из другой части урока]** → они остаются кандидатами словаря, если попадут в случайный пул. Окно можно расширить константой.
- **[Слово без уроков (добавлено вручную)]** → `close` = только слова занятия, иначе прежний пул. Поведение не хуже текущего.

## Migration Plan

Схема базы и формат синхронизации не меняются, миграций нет. Собранные сессии хранят варианты в элементах и не пересчитываются. Откат — прежний деплой.
