# Дизайн

## Порядок относительно `limit-new-to-nearest-lesson`

Изменение `limit-new-to-nearest-lesson` уже в `main`, но ещё не архивировано: его задача 7 (проверка на дев-боте) открыта. Оно правит требование «Интервалы и сохранение ответа», которое правит и это изменение. Дельта ниже написана поверх **его** текста — с тремя режимами записи, — чтобы архивация в любом порядке не потеряла режимы.

## Решение 1: четыре градации оценки

`recordAnswer` получает `status` проверки, а не только булев `correct`. Отображение:

```
status==='correct' && быстрый && тип ∈ FAST_TYPES  →  Rating.Easy  (4)
status==='correct'                                 →  Rating.Good  (3)
status==='almost'                                  →  Rating.Hard  (2)
иначе                                              →  Rating.Again (1)
```

`correct` остаётся отдельным полем события и сохраняет прежний смысл «ответ полностью правильный». От него по-прежнему зависят сводка навыков (`succeeded`), сброс `cleanAssemblies` и добавление дополнительной попытки. Разводим два вопроса, которые раньше отвечались одним битом: «что показать и чему учить дальше» (`correct`) и «насколько подвинуть срок» (`rating`).

Поэтому «Почти» остаётся ошибкой навыка и закрывает гейт написания, но расписание получает Hard. Событие уже хранит и `correct`, и `rating`, формат синхронизации не меняется.

## Решение 2: время ответа только на заданиях с выбором

`FAST_TYPES = {recognition, listening, comprehension}`, порог `FAST_ANSWER_MS = 3500`.

В сборке, написании и пропуске длительность определяется длиной ответа и скоростью набора: «быстро» там означает «короткое слово», а не «легко вспомнил». Нормировать по длине можно, но подбирать коэффициенты вслепую — значит вносить в расписание шум под видом сигнала. Время там не читается.

Порог общий для трёх типов, хотя у аудирования и понимания на слух в него попадает воспроизведение (около секунды). Это сознательный перекос в консервативную сторону: `Easy` там будет выпадать реже, чем в узнавании, и ни одна карточка не получит завышенный интервал из-за того, что аудио оказалось коротким. Порог — одна экспортируемая константа: когда накопится история `responseTimeMs`, его можно пересчитать по фактическому распределению.

`Easy` влияет на расписание только в режиме `scheduled`: `preview` при верном ответе срок не двигает, `practice` не двигает никогда.

## Решение 3: разброс интервалов

`DefaultInitSeedStrategy` в `ts-fsrs` строит сид из `review_time`, `reps` и произведения `difficulty * stability`. Все три величины детерминированы для пары (карточка, момент ответа), поэтому `enable_fuzz:true` не делает планировщик случайным: тест с фиксированной датой и фиксированным состоянием получает тот же интервал, что и раньше, — просто другой. Отдельная стратегия сида не нужна.

## Решение 4: гейт написания в одну сборку

`spellingUnlockedFor` меняет `>=2` на `>=1`. Прогон выбора типа для слова с аудио, четырьмя вариантами и двумя слогами:

```
до:    1 recognition  2 assembly  3 listening  4 comprehension  5 recognition  6 assembly  7 spelling
после: 1 recognition  2 assembly  3 spelling   4 listening      5 comprehension
```

Логика «ошибка в написании закрывает гейт» не меняется: `cleanAssemblies` обнуляется на ошибке в написании и растёт на верной сборке.

## Решение 5: пропуск с вариантами как ступень вниз

Новый тип упражнения не вводится. Ступенью служит тот же `type:'cloze'` с заполненным `options`: `ClozeExercise` рисует четыре кнопки вместо поля ввода, когда `options.length===4`.

Это решение выбрано вместо отдельного `cloze-choice`, потому что новый `ExerciseType` потянул бы за собой сводку навыков, статистику, `SKILL_NAMES` и формат синхронизации — ради варианта подачи одного и того же вопроса. Проверка ответа общая: выбранный текст уходит в тот же `checkTextAnswer`, поэтому «Почти» работает и в вариантах.

Дистракторы берутся из `answer` других живых карточек пропуска через общий `optionsAmong`: он уже отбрасывает совпадающие по нормализации ответы и требует ровно четырёх различных. Пул читается только при ошибке в пропуске, как пулы слов и фраз.

## Решение 6: карточки, которые не даются

Порог `LEECH_LAPSES = 8` — значение Anki по умолчанию. Список ограничен двадцатью строками.

`progress()` уже обходит все состояния через `eachState`; провалы берутся из `card.lapses`, который и так есть в состоянии и в формате синхронизации. Для подписи нужен текст карточки, поэтому `StatsSource` получает `labelsOf(refs)` — по одному запросу на три таблицы, только для отобранных карточек.

Планировщик не трогаем: раздел сообщает пользователю, что карточка не идёт, и оставляет решение ему. Автоматическая приостановка без экрана управления приостановленными карточками создала бы материал, который молча исчез из программы.

## Решение 7: состав сводки навыков

`SKILL_TYPES` приводится к списку предлагаемых сейчас типов: `recall` уходит, `comprehension` добавляется. Ответы на `recall` остаются в общем числе записанных ответов и в истории по дням — исчезает только строка типа, который больше нельзя получить.
