## Context

Репозиторий содержит только OpenSpec, навыки и начальный коммит; кода и существующих спецификаций нет. Мотивация описана в proposal.md. Пользователь согласовал личное веб-приложение с локальным хранением, затем передал концепцию: https://chatgpt.com/share/6aa98ecd-7e6c-83ed-a611-29c643a75698. Требования текущей переписки приоритетнее примеров из неё: картинки и IPA нужны сразу, подготовка привязана к занятиям, последующие наборы и даты добавляются самим пользователем.

Начальные данные зафиксированы в seed-lessons.md. 18 сентября 2026 года — дата первого предстоящего урока из контекста беседы; это редактируемая дата конкретного набора, а не константа планировщика. Для 1.1 дата неизвестна. Предположение для MVP: стандартный новогреческий, не специальная кипрская диалектная транскрипция; зона календаря Asia/Nicosia с настройкой пользователем.

## Goals / Non-Goals

**Goals:** чистые проверяемые функции обучения; отсутствие сетевой зависимости в основной тренировке; долговечные данные; готовые исходные карточки; одинаковая модель для начальных и любых добавленных уроков.

**Non-Goals:** серверный рендеринг, собственная формула интервального повторения, монорепозиторий, обязательная генерация контента во время работы, оценка устной речи. Изменение данных пользователем не должно требовать изменения кода.

## Decisions

### 1. Стек и границы модулей

React + TypeScript + Vite, обычные CSS-переменные и доступные компоненты, React Router, Dexie/IndexedDB, ts-fsrs, vite-plugin-pwa, Vitest и Playwright. Версии закрепляются lock-файлом при реализации после проверки совместимости. Next.js из исходной переписки рассмотрен: серверных страниц и API в согласованном сценарии нет, поэтому статическое приложение Vite уменьшает число компонентов системы. Redux, TanStack Query и монорепозиторий на старте не требуются.

Структура: src/app (маршруты и оболочка), src/features/{lessons,words,learning,progress,backup}, src/domain (типы, импорт, проверка, очередь, адаптер расписания), src/storage, src/content, src/shared. Domain получает часы и генератор случайности параметрами; не импортирует React, Dexie или браузерные API. Работа с хранилищем сосредоточена в небольших операциях, без универсальной платформы репозиториев.

### 2. Модель данных

- Lesson: id, title, targetDate (локальная YYYY-MM-DD или null), status (upcoming/completed), wordIds, createdAt, updatedAt. Можно добавить любой следующий урок, изменить дату или отметить проведённым. Число наборов не ограничивается двумя начальными.
- Word: id, greek, russian, article, ipa, pronunciationSegments, imageAssetId, audioAssetId, examples (массив {greek, russian, targetSpans, source, verified}), contentStatus, sourceMastered, createdAt, updatedAt, deletedAt. Разметка хранит диапазоны греческого текста и IPA, тип сочетания и русское объяснение. Артикль сохраняется в отображаемом greek.
- Asset: id, kind, mimeType, blob, checksum, source, license/creationMethod, alt. Аудио и картинки доступны локально; внешние ссылки не являются единственной копией.
- LearningState: wordId, сериализуемая карточка выбранной версии FSRS, introducedAt, счётчики ответов и ошибок по каждому навыку. Поля состояния FSRS сохраняются полностью через адаптер, без ручного урезания.
- ReviewEvent: id, sessionId, itemId, wordId, snapshot слова, exerciseType, mode (scheduled/practice), objectiveCorrect или null, selfRating или null, итоговая rating, responseTimeMs, createdAt, localDate, состояние FSRS до/после для scheduled.
- Session: id, planDate, items с фиксированными вариантами, currentIndex, activeTimeMs, status. Item имеет стабильный id и ссылку на ReviewEvent после ответа.
- Settings: timezone, newWordsPerDay (10), sessionSize (20, минимум 2), schemaVersion. Прогресс и дневные счётчики вычисляются из событий и introducedAt, а не из UI.

Одинаковые NFC-normalized greek+russian в разных уроках используют одну Word и общее состояние повторения; членство хранится в Lesson. Другой перевод — отдельная запись. Конфликт перевода при импорте показывается в предпросмотре. Удаление слова мягкое, история остаётся; удаление из одного набора не удаляет слово из других. Изменение греческого слова помечает зависимые аудио/IPA/разметку как непроверенные; перевод не сбрасывает историю.

### 3. Импорт и исходный контент

Два режима парсинга: TSV и чередование непустых строк. Пустые строки и известные служебные строки Quizlet исключаются; позиция Mastered отмечает оставшиеся записи как исходно освоенные. Предпросмотр показывает режим, пары, исключённые строки, ошибки, дубликаты и привязку к набору. До явного сохранения БД не меняется. Дубликаты определяются после NFC, нормализации регистра и пробелов с сохранением ударения. Импорт набора выполняется транзакцией.

Поле третьей TSV-колонки обозначается IPA; непроверенная пользовательская запись хранится как пользовательская, не как верифицированная фонетика. Обе исходные коллекции загружаются однократно с устойчивыми id и маркером версии seed: повторный запуск и обновление не восстанавливают удалённые пользователем слова.

Для 63 исходных слов заранее подготовить картинки и локальные аудиофайлы. Для конкретных предметов — ясные изображения; для глаголов и наречий — иллюстрация ситуации. Можно использовать собственные векторные иллюстрации или лицензированные/сгенерированные изображения; emoji не заменяют пакет картинок. Проверить фонетику каждого слова по авторитетным словарным/учебным источникам, записать ссылки и вариативность, затем прослушать аудио. Автоматическая транслитерация всей греческой орфографии не реализуется. Новые слова можно учить сразу и вручную дополнять IPA, картинкой, аудиофайлом и примерами употребления с переводами в редакторе. Автоматическое обогащение будущих наборов — отдельное улучшение, не обещание MVP.

Для каждого из 63 исходных слов подготовить минимум одно короткое предложение на стандартном новогреческом и точный русский перевод. Предпочитать простые бытовые ситуации; предложение показывает значение именно этой карточки, без большого количества незнакомой лексики. Проверить грамматику, ударения и естественность по учебным/словарным источникам, зафиксировать происхождение. Диапазоны targetSpans выделяют само слово или его употреблённую грамматическую форму. Все примеры сохраняются вместе со словом в БД и полной копии. В редакторе можно добавить, изменить и удалить пример; если его нет, интерфейс предлагает добавить. Озвучка предложений не обязательна в MVP и не заменяет аудио самого слова. Отдельный пятый тип упражнения на контекст не требуется: примеры включены в знакомство и обратную связь после ответа, скрыты во время проверки.

### 4. Подготовка к нескольким урокам

Даты хранятся как календарные значения, события — UTC; расчёты дней используют настроенную зону, не деление миллисекунд на 24 часа. Сортировать будущие уроки по targetDate, затем createdAt/id. Для каждой даты считать уникальные ещё не введённые слова накопительно по всем урокам до этой даты. Требуемый дневной темп — максимум ceil(накопительное число новых / max(1, число дней до этой даты)). Это учитывает несколько ближайших занятий. Одно слово в двух наборах считается один раз с самой ранней датой.

Дневной бюджет ограничен newWordsPerDay и уменьшается на число уникальных слов, уже введённых сегодня. Если расчётный темп выше ограничения, показывать нехватку времени и настройку лимита без автоматического изменения. Среди новых сначала брать слова ближайшего срока, затем более позднего; после покрытия планового темпа доступные места дневного бюджета можно отдать недатированным или прошлым наборам. Резерв под новые в сессии — min(оставшийся дневной бюджет, ceil(sessionSize/2)); остальные места — relearning, overdue, due. Пустые места разрешено заполнить другой категорией, сохраняя минимум одно старое повторение при его наличии и не превышая дневного бюджета новых. Число упражнений и уникальных слов явно различается.

Новый item сначала показывает знакомство, затем проверку recall. Введённым слово становится после первой сохранённой проверки. Нет бесконечного добавления ошибочных карточек к текущей сессии: Again назначает краткий срок через FSRS, повторение попадёт в следующую сессию после наступления срока. Экран результата предлагает повторить ошибки, если они уже доступны, или сообщает ближайший срок.

Перенос даты пересчитывает будущие планы, не стирает события и сроки FSRS. Существующая сессия сохраняет состав; новая получает новый план. Прошедший урок не исчезает, неподготовленные слова продолжают попадать в обычную очередь. День урока — режим догоняющей подготовки с делителем один, без гарантии освоения к времени занятия. Дата означает календарный срок, время урока не предполагается.

### 5. FSRS и выбор упражнений

Использовать публичный API [ts-fsrs](https://github.com/open-spaced-repetition/ts-fsrs) через адаптер. Параметры по умолчанию библиотеки закрепить вместе с версией. Scheduled-ответ меняет FSRS один раз в одной транзакции с событием и позицией сессии. Unique itemId предотвращает двойные записи, в том числе из другой вкладки; оптимистическая проверка предыдущей версии состояния предупреждает конфликт вкладок.

Для правильного объективного ответа автоматически Good; для неверного и Почти — Again. Для recall пользователь выбирает Again/Hard/Good/Easy после раскрытия. Самооценка не записывается как объективная точность. До срока можно тренировать вручную, включая подготовку к уроку; mode=practice фиксирует результат навыка, но не сдвигает FSRS. Так подготовка не создаёт ложных длинных интервалов.

При выборе навыка использовать последние 10 событий каждого навыка. Сначала проверять ещё не проверенные доступные навыки в порядке recall, recognition, spelling, listening; затем выбирать минимальную долю успехов, при равенстве — давно проверявшийся. После двух одинаковых типов подряд выбирать следующий доступный. Это эвристика выбора упражнения, не оценка вероятности памяти. Показанные пользователю значения сопровождаются числом попыток. Для recall успехом в этой эвристике считается самооценка выше Again.

Написание: NFC, trim, схлопывание пробелов, греческий lower-case и сигма. Сначала точное совпадение; затем сравнения без ударения и без ожидаемого артикля для конкретного объяснения Почти; остальные ошибки показываются посимвольно. Артикли и ударения не теряются в эталонном ответе. Recognition получает уникальные переводы, listening — уникальные написания; при недостатке вариантов использовать recall. Не использовать исходную картинку и раскрывающий alt в recognition, если они выдают перевод.

### 6. Экраны

Сегодня: ближайшие уроки и сроки, требуемый темп, сколько новых осталось на сегодня, повторения, Начать, Продолжить незавершённое. Уроки: список, добавить набор, дата, статус, содержимое, подготовка набора. Слова: поиск, фильтр по уроку и состоянию, карточка и редактирование. Ещё: статистика, дневной лимит, размер сессии, зона, импорт/экспорт, полная копия.

Сессия: закрытие, номер упражнения, прогресс; знакомство/recognition/recall/listening/spelling; отдельное состояние ответа и Далее; результат. Выход сохраняет уже записанные ответы. Основная кнопка не прыгает при появлении обратной связи. Базовая палитра #F7F7F5/#FFFFFF, текст #171717, акцент #2563EB; system-ui, крупное греческое слово, цели касания от 44 px. Базовая проверка 390×844 плюс 360 px и широкий экран. Нет выдуманного имени, уровня A2 и счётчиков из примеров переписки.

### 7. Офлайн и копии

[Vite PWA precache](https://vite-pwa-org.netlify.app/guide/service-worker-precache) хранит оболочку и исходный пакет, IndexedDB — пользовательские данные и медиа. Список необходимых файлов проверяется перед сообщением Готово офлайн. AudioProvider сначала использует Asset blob, затем доступный el-GR системный голос для новых слов. Если голоса нет — аудирование исключается, другие упражнения доступны. Восстановленные медиа также читаются из Asset, не только из HTTP-кеша.

Полная копия: формат Dexie export/import с внешней проверкой идентификатора приложения/версии и всех обязательных таблиц/ссылок. [Документация Dexie](https://dexie.org/docs/ExportImport/dexie-export-import) описывает перенос базы; реализация дополнительно проверяет контракт приложения. Проверить файл во временной базе, показать объёмы и дату, предложить скачать текущую копию, запросить подтверждение замены; заменить рабочие таблицы атомарно, при ошибке оставить старые данные. TSV — отдельный экспорт слов без обещания сохранить обучение. Ограничения размера файлов/медиа явно отображать до записи, проверять MIME и чтение файла; конкретные лимиты задать в UI после оценки размера исходного пакета.

### 8. Проверки

Vitest: реальные тексты импортов, дедупликация, Unicode, артикль/ударение, календарь/переходы зоны, несколько сроков, дневные лимиты, FSRS с фиксированными часами, отсутствие пересчёта practice, ранжирование навыков. Интеграция с тестовой IndexedDB: транзакции, повторная отправка, конфликт вкладок, seed-once, сохранение сессии, повреждённый импорт и полный перенос с blob.

Playwright на production build: первый запуск → урок → карточка → четыре режима → результат → перезапуск; создание 1.3 на новую дату; перенос даты; офлайн после закрытия страницы; backup/restore в чистом профиле; работа без голоса и ошибки хранилища. Проверить клавиатуру, мобильную ширину, фокус и подсказки, не выдающие ответ. Ручная проверка всех 63 IPA/аудио/изображений/примеров — отдельное условие готовности.

## Risks / Trade-offs

- Неверная фонетика → проверенные данные с источниками, отсутствие непроверенной автоматической разметки; контентная проверка обязательна до готовности.
- Локальные голоса различаются → исходный набор использует файлы; новые слова имеют явное состояние недоступного аудио.
- Браузер может очистить данные → экспорт полной копии и понятная информация о локальном хранении, запрос persistent storage где доступен.
- Срок урока не гарантирует запоминание → показывать объём и фактические ответы, не обещать освоение по одному просмотру.
- Подготовка всего медиапакета требует времени → завершать 1.2 первым внутри реализации, но не объявлять MVP готовым без полного 1.1.
- Универсальные новые наборы не обогащаются сами → редактор поддерживает ручные данные; автоматизация обогащения не блокирует основную тренировку.

## Migration Plan

Первое развёртывание — статический production build по HTTPS; локально localhost. База версии 1 и однократный seed. Перед будущей миграцией схемы предлагать полную копию; тестировать миграцию на сохранённой базе. Обновление service worker применять после завершения/сохранения сессии. Откат статических файлов допустим только при совместимой схеме; несовместимую версию БД нельзя молча пересоздавать. В этой задаче создаются плановые документы; публикация приложения не является этапом планирования.
