## Context

См. proposal.md. Новое слово сейчас получает recall и немедленную самооценку после знакомства. Сессии хранятся в IndexedDB; старые события и резервные копии содержат recall.

## Goals / Non-Goals

**Goals:** полностью убрать самооценку из текущего интерфейса; сохранить историю и атомарность ответов.

**Non-Goals:** удалять исторические оценки или менять базовый алгоритм интервалов.

## Decisions

1. Знакомство — отдельный проход по новым словам в порядке очереди, затем задания в том же порядке. Показанные слова сохраняются в сессии; просмотр не создаёт ReviewEvent и не пересчитывает FSRS. Это даёт промежуток между показом и проверкой при нескольких новых словах. Если новое слово одно, доступные задания других слов идут перед его проверкой; если других слов нет, проверка следует сразу, без самооценки.
2. Новые слова начинают с выбора перевода; при отсутствии четырёх уникальных вариантов — сборка, а для одной плитки — написание. Повторения используют существующую эвристику без recall. Старые неотвеченные recall преобразуются при открытии занятия; отвеченные записи сохраняются.
3. UI передаёт объективную правильность. Хранилище назначает Good верному ответу и Again ошибке, «Почти» или «Не знаю». Старые nullable-события остаются читаемыми; новые ответы с correct=null отклоняются.
4. «Не знаю» доступно до ответа во всех заданиях. Сначала сохраняется ошибка, затем показывается правильный ответ. Любая ошибка добавляет одну дополнительную попытку для этого слова за занятие после двух доступных заданий или в конце очереди. Дополнительная попытка имеет mode=practice и не сдвигает интервал; повторная ошибка не создаёт бесконечный цикл. Добавление попытки атомарно с сохранением ошибки.
5. Для совместимости сохраняем тип recall в модели истории, но исключаем его из генерации и отображения. Подготовка старой сессии выполняется транзакционно; миграция схемы базы не нужна, новые поля опциональны.

## Risks / Trade-offs

- Выбор ответа допускает угадывание → остаются сборка и написание по истории навыков.
- Маленькая сессия не обеспечивает длинный промежуток → используем все доступные другие слова, без искусственного ожидания.
- Дополнительные попытки увеличивают занятие → не более одной на каждое слово; исходный лимит относится к основной очереди.
- Несколько вкладок → сохраняем проверку версии состояния и идемпотентные идентификаторы событий.

## Migration Plan

Подготовить старые активные сессии при входе; сохранить историю без изменений. Проверить новую и продолжаемую сессию, перезагрузку и запись ошибок. Изменение остаётся в отдельной ветке; публикация выполняется отдельно.
